# Toolchain

Every command that compiles Swift uses one pinned toolchain: `swift run`, the Gradle cross-compile, `swift package dump-package` for Xcode, and `swift sdk install`. So the toolchain and the Swift SDKs always come from the same release.

```bash
uv run nucleant toolchain install            # swiftly, the pinned Swift, the SDKs nucleant.toml needs
uv run nucleant toolchain install --android  # the Android Swift SDK regardless of nucleant.toml
uv run nucleant toolchain install --wasm     # the wasm Swift SDK regardless of nucleant.toml
uv run nucleant toolchain show               # what is resolved and installed
```

```text title="nucleant toolchain show"
Swift 6.3.3 (swiftly): ~/Library/Developer/Toolchains/swift-6.3.3-RELEASE.xctoolchain/usr/bin/swift
  android  swift-6.3.3-RELEASE_android  (installed)
  wasm     swift-6.3.3-RELEASE_wasm  (installed)
```

You rarely have to run `install` yourself. The first command that needs Swift installs it, and the first `android run` installs the Android Swift SDK.

---

## swiftly and the pinned Swift

```toml title="nucleant.toml"
[toolchain]
swift = "6.3.3"
swiftly = true
```

With `swiftly = true` (the default):

1. **swiftly** is installed if it is missing. On macOS that is the user-domain `.pkg`, on Linux the tarball for the machine's architecture. It is installed for the current user with `--no-modify-profile`, so your shell profile is not edited.
2. **Swift `[toolchain] swift`** is installed with `swiftly install 6.3.3` if it is missing.
3. nucleant asks that toolchain where its `swift` is (`swiftly run swift -print-target-info +6.3.3`) and from then on calls it **by absolute path**.

Your global default toolchain, the one `swift` on your PATH runs, is never changed.

With `swiftly = false`, or on a host swiftly doesn't support, nucleant uses `swift` from PATH and warns when its version is not the pinned one.

!!! tip "Running Swift yourself"
    Plain `swift run` in the project uses whatever `swift` is on your PATH. To use the project's toolchain, run `swiftly run swift run +6.3.3`, or the path `nucleant toolchain show` prints.

## Swift SDKs: Android and wasm

Android and WebAssembly are cross-compiled from macOS or Linux with Swift SDKs. The SDK's id, URL and checksum all follow from the toolchain version:

| Kind | Id | Installed when |
|---|---|---|
| Android | `swift-6.3.3-RELEASE_android` | `nucleant.toml` has `[android]`, or `--android`; also on the first `android run` |
| wasm | `swift-6.3.3-RELEASE_wasm` | `nucleant.toml` has `[wasm]`, or `--wasm` |

They are installed with `swift sdk install`, checked against the SHA-256 that swift.org publishes for that release. To build with a different SDK, name it:

```toml title="nucleant.toml"
[toolchain]
android_sdk = "swift-6.3.3-RELEASE_android"
wasm_sdk = "swift-6.3.3-RELEASE_wasm"
```

## Android SDK, NDK and Java

The Android tools are resolved the same way ksproject did. For each tool, the first match wins:

1. **The environment**: `ANDROID_HOME`, `ANDROID_NDK_ROOT`, `JAVA_HOME`.
2. **nucleant.toml**: `[android] sdk_path`, `ndk_path`, `java_path`.
3. **A nucleant-managed install**: Android cmdline-tools, the SDK platform and build tools, the NDK (`ndk = "28c"` is r28c), CMake and the emulator.

Java must be 21 or older, because `sdkmanager` crashes on Java 22 and newer. nucleant takes the first JDK that fits: `JAVA_HOME`, `java_path`, sdkman's current Java, then the system's. If none fits, it installs Temurin 21 through sdkman.

The managed install goes to `~/.nucleant/android-sdk` with `global_tools = true` (the template's default), shared by every project. With `global_tools = false` it goes to the project's own `./.nucleant/`. `global_tools_path` moves the shared root.

```bash
uv run nucleant android get-path sdk       # where each one was found
uv run nucleant android get-path ndk
uv run nucleant android get-path emulator
```

## XcodeGen

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) 2.45.4. nucleant downloads it once into `~/.nucleant/xcodegen/`. You don't install it, and Homebrew's copy isn't used.
